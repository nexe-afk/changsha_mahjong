# Claude 4.7 提示词 — AI 玩家策略（集成参考项目）

## 原目标模型: gpt-4.1/codex → Claude 4.7

## 专业背景与项目参考

**Role**: 你是麻将 AI 策略专家，深入分析过以下开源项目的 AI 决策逻辑：
- **mahjong-helper** (⭐2.3k+, GitHub: EndlessCheng/mahjong-helper): 支持雀魂、天凤的实时 AI 助手，提供牌效分析（打哪张牌期望值最高）和防守分析（规避放炮）。它的核心是出牌评分系统和危险性加权。
- **Akagi** (⭐788, GitHub: shinkuan/Akagi): 实时分析雀魂的 AI 助手，支持自定义模型，采用中间人代理(MITM)架构。
- **Mortal** (⭐1.4k+, GitHub: Equim-chan/Mortal): 基于 Rust 和深度强化学习的超强麻将AI，代表天花板级水平。

**你的任务**：用纯 JavaScript (ES6+) 实现长沙红中麻将的三档难度 AI 玩家策略模块。参考 mahjong-helper 的评分体系和防守加权逻辑，但不追求 Mortal 的深度强化学习级别——保持基于规则的清晰可解释设计。

**参考 mahjong-helper 的关键设计点**:
1. **牌效率评分**: 每张牌的「孤立度」和「搭子数」是核心指标。孤张（无邻牌）分数低，双面搭子（有两张邻牌）分数高。
2. **防守加权**: 当其他玩家听牌迹象明显时，打牌权重从「效率优先」切换为「安全优先」——危险牌（已出现过的牌、生张）被降权。
3. **红中处理**: 红中是绝对安全牌（因为不能被吃碰），但也是万能牌，mahjong-helper 的策略是「除非听牌，否则留红中」。
4. **听牌检测**: 打出某张牌后，如果剩余牌能胡，则该牌扣分（AI 倾向于听牌）。

**将这些策略融入你的评分系统**：

1. **出牌评分系统**:
   - 对每张手牌计算分数，选最低分打出
   - 评分规则: 成对+20, 左搭子+10, 右搭子+10, 两面搭+15, 听牌价值+30, 边张(1/9)-5, 已碰牌色-10, 红中-9999（永不弃）
   - 每张牌独立评分，评分理由结构化存储

2. **动作决策**:
   - aiDecideAction 返回 'hu' | 'peng' | 'gang' | 'pass'
   - 能胡时必须返回 'hu'（优先级最高）
   - 杠决策有概率因素（普通模式50%，困难模式70%，简单模式30%）
   - 碰决策阈值制：碰后预计听牌张数 > 阈值才碰

3. **三档难度**:
   - easy: discardNoise=0.3, pengThreshold=5, huBlindChance=0.3
   - normal: discardNoise=0.05, pengThreshold=3, huBlindChance=0.05
   - hard: discardNoise=0, pengThreshold=1, huBlindChance=0

**I/O Contract**:
```
aiDecideDiscard(hand: number[], melons: object[], difficulty='normal') → tileCode: number
aiDecideAction(playerIdx: number, tile: number, availableActions: string[], difficulty='normal') → 'hu' | 'peng' | 'gang' | 'pass'
getDifficultyParams(level: string) → { discardNoise, pengThreshold, huBlindChance }
```

**Constraints**:
- 所有函数纯函数（只读 gameState 不写入）
- 有红中时永不弃红中
- 能胡时永远返回 'hu'
- 每次调用入参相同则结果一致（除 noise 因素外）
- 不要用机器学习或概率模型
- 评分规则写在注释中

**Output Format**: 单个文件 ai.js（约120行），难度常量 + 三个导出函数，规则写在注释里。

**Verification Plan**（参考 mahjong-helper 的测试覆盖）:
1. 有红中的手牌永不弃红中
2. 能胡时永远返回 'hu'
3. 简单模式 ~30% 非最优出牌
4. 困难模式 0% 随机出牌
5. 同一手牌调用结果一致（纯函数）
6. 手牌14张时必须返回有效牌编码
7. 附带5个测试场景覆盖三种难度
