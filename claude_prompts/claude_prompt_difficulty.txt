# Claude 4.7 提示词 — 动态难度调整（集成参考项目）
## 原模块: Module 4 (prompts.json) / 04 (prompts_v2)
## 原目标模型: gpt-4.1/codex → Claude 4.7
## 参考项目: archer (moxcomic), nanoserver (lonng)

---

## 专业背景与项目参考

**Role**: 你是自适应难度系统设计师，考察过 archer (天凤9.7段AI) 和 nanoserver (生产级棋牌后端) 的设计思路。archer 的多层决策因子加权是你的核心灵感来源——它根据牌局阶段(序盘/中盘/终盘)切换 AI 行为模式，这套逻辑可以简化为难度阶梯沿用到这里。

**Task**: 用纯 JavaScript (ES6+) 实现长沙红中麻将的动态难度调整系统。系统根据玩家最近5局表现自动升降AI难度级别，使玩家始终处于「心流」状态。

**Context**:
- 数据持久化: localStorage
- 接口依赖: ai.js 的 getDifficultyParams(level)
- 难度参数通过 window.difficultyParams 全局对象传递
- 触发时机: 每局游戏结束后自动调用
- 非侵入式设计，不修改 ai.js

**参考 archer 的难度设计思路**：
archer 在天凤平台上达到9.7段的秘诀之一是多层决策因子加权——同一手牌在不同牌局阶段适用不同策略。类比到这里，三个难度级别本质上就是三套「决策因子权重配置」：
- Easy: 防守因子权重高（保守，少碰少杠）
- Normal: 效率因子权重中（进攻防守均衡）
- Hard: 进攻因子权重高（激进碰杠，最大听牌追求）

**Detailed Requirements**:

1. **PlayerTracker 类**: recordGame(result) / getRecentGames(n) / getWinRate(n=5) / getAvgScore(n=5) / getStreak() / reset()

2. **难度调整逻辑**: 连胜≥3局或平均分>20→升一级；连败≥3局或平均分<5→降一级；其他保持

3. **DDAManager 类**: init() / applyParams() / onGameEnd(result)

**I/O Contract**:
```
PlayerTracker(storageKey='mj_player_tracker')
  recordGame({ score, isWin, duration }) → void
  getWinRate(n=5) → number
  getStreak() → number

adjustDifficulty(currentLevel, tracker) → 'easy' | 'normal' | 'hard'

DDAManager.init() → void / applyParams() → void / onGameEnd(result) → void
```

**Constraints**:
- localStorage key: 'mj_dda'
- 所有阈值常量定义在文件顶部
- 非侵入式，不修改 ai.js
- 纯函数式调整逻辑

**Output Format**: difficulty.js（约150行），PlayerTracker + adjustDifficulty + DDAManager。

**Verification Plan**:
1. 新玩家从 'normal' 开始
2. 连胜3局→升级到 'hard'
3. 连败3局→降级到 'easy'
4. 升级后 discardNoise↓, pengThreshold↓
5. localStorage 刷新后保持
6. 重置回到 'normal'
