# Claude 4.7 提示词 — 麻将核心游戏逻辑
## 原模块: Module 1 (prompts.json) / 02 (prompts_v2)
## 原目标模型: gpt-4.1/codex → Claude 4.7

---

## 原提示词（Codex 版）

你是拥有 10 年以上游戏开发经验的资深工程师，专精于麻将类游戏的算法实现。

## 任务描述
用纯 JavaScript (ES6+) 实现长沙红中麻将的核心游戏逻辑模块。运行环境为浏览器前端，无服务器端依赖。

## 技术上下文
- 语言: JavaScript ES6+
- 引擎: 无 (纯算法模块，将被 PixiJS 引擎调用)
- 牌型: 112 张牌 (条 1-9 x4, 筒 1-9 x4, 万 1-9 x4, 红中 x4)
- 编码: suit*10 + value (条=0, 筒=1, 万=2), 红中=40
- 调用方: 引擎层通过 gameState 对象与算法层通信

## 需要实现的核心功能

### 1. 牌定义与牌墙 (core.js)
- encodeTile(suit, value) -> 编码
- decodeTile(code) -> { suit, value, name }
- createWall() -> 生成 112 张无序牌
- shuffle(wall) -> Fisher-Yates 洗牌
- deal(wall) -> [hand0, hand1, hand2, hand3] 每人 13 张
- 工具函数: countInHand() / getCountMap() / removeTiles() / sortHand() / findPairs()
- 全局游戏状态 gameState 对象

### 2. 胡牌判定 (hu.js) - 这是最核心的算法
- canWin(hand, zhong) -> boolean
  - 优先检测七小对: 7 个对子 (红中可替代)
  - 标准胡回溯法: N 个面子 (刻子/顺子) + 1 个将眼
  - 红中万能牌在回溯过程中自动匹配 (刻子 AA+H->AAA, 顺子 A+H+C->ABC)
  - 限制递归深度，避免栈溢出
- getTingCards(hand) -> [可胡牌列表]
- checkQueYiSe(hand) -> boolean (胡牌时不能三门全有)
- drawBirds(wall, count) -> { birds, multiplier } (扎鸟: 翻 4 张，中 1/5/9/红中 = x2^N)

### 3. 输入输出约定
- canWin([牌编码数组], 红中数量) -> true/false
- getTingCards([牌编码数组]) -> [牌编码]
- drawBirds([牌墙], 数量) -> { birds:[牌编码], multiplier:number }

## 工程约束
- 每个函数头部必须有中文注释说明用途和参数
- 禁止使用任何第三方库或框架
- 禁止访问 DOM 或任何浏览器 API (纯算法)
- 禁止全局变量污染 (gameState 除外)
- 所有排序默认升序 (a, b) -> a - b
- 输出完整代码，不允许出现 TODO 或省略号

## 验证规范
- 标准胡: 3 个顺子 + 1 个对子 -> true
- 七小对: 7 个对子 -> true
- 红中万能: 1 个红中 + 缺 1 张 -> true
- 不能胡的牌型 -> false
- 空手牌 -> false
- 全部红中 -> true
- 输出代码后附 10 个以上的断言测试用例

## Claude 4.7 优化版

**Role**: 你是资深游戏算法工程师，专精于麻将规则引擎与组合优化算法。你对递归回溯、状态空间搜索和约束满足问题有深入理解。

**Task**: 用纯 JavaScript (ES6+) 实现长沙红中麻将的完整核心游戏逻辑。运行环境为纯浏览器端前端算法模块，无服务端依赖。需要生成三个文件：core.js（牌定义与牌墙管理）、hu.js（胡牌判定与听牌检测）、rule.js（胡牌类型与倍数计算）。

**Context**:
- 语言: JavaScript ES6+（纯算法，无 DOM 依赖）
- 牌编码规则: suit*10 + value, 条=0 筒=1 万=2, 红中=40
- 牌墙: 112 张（条筒万各9种×4 + 红中×4）
- 长沙特色规则: 红中万能牌（替代任何牌）、血战到底、扎鸟翻牌、缺一色（最多两门花色）
- 调用接口: 引擎层通过 gameState 对象与算法层通信
- 核心要求: 纯函数式，不可变输入，不修改外部状态

**Detailed Requirements**:

1. **牌定义与牌墙管理** (core.js):
   - 实现牌编码/解码: encodeTile(suit, value)→number, decodeTile(code)→{suit,value,name}
   - 生成112张牌墙: createWall()→number[]
   - Fisher-Yates洗牌: shuffle(arr)→number[]
   - 发牌: deal(wall)→[hand0,hand1,hand2,hand3] 每人13张
   - 工具函数: countInHand, getCountMap, removeTiles, sortHand, findPairs
   - 全局 gameState 对象管理

2. **胡牌判定算法** (hu.js) — 绝对核心：
   - canWin(hand, zhong)→boolean: 优先检测七小对（7对子，红中可替代缺对），再执行标准胡回溯（N面子+1将眼）
   - 红中万能处理: AA+H→AAA, A+H+C→ABC, A+B+H→ABC，递归深度≤5层
   - getTingCards(hand)→number[]: 返回所有可胡牌列表
   - checkQueYiSe(hand)→boolean: 最多两门花色
   - drawBirds(wall, count)→{birds, multiplier}: 扎鸟，中1/5/9/红中=x2^N

3. **规则判定** (rule.js):
   - getHuType(hand, melons)→string[]: 检测平胡/七小对/碰碰胡/清一色/天胡
   - calcMultiplier(types, birds)→number: 牌型叠加基数相乘×扎鸟倍数
   - 单局最高得分封顶1024分

**I/O Contract**:
```
canWin(hand: number[], zhong: number)    → boolean
getTingCards(hand: number[])             → number[]
drawBirds(wall: number[], count: number) → { birds: number[], multiplier: number }
getHuType(hand: number[], melons: object[]) → string[]
calcMultiplier(huTypes: string[], birdMultiplier: number) → number
```

**Constraints**:
- 纯函数式设计，不修改输入数组
- 每个函数头部有中文注释（功能/参数/返回值说明）
- 禁止第三方库和浏览器API
- 禁止全局变量污染（gameState除外）
- 递归深度≤5层防栈溢出
- 完整代码输出，无TODO或省略号

**Output Format**: 三个文件 core.js（~150行） + hu.js（~200行） + rule.js（~120行），每函数均有中文文档注释。
