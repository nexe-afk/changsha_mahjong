### 01. 支付系统核心（合并原01+02+04）

**Role**: 你是支付架构师和后端开发者，精通 Node.js 支付系统设计和多币种钱包管理。你熟悉 REST API 签名验证和区块链交易确认机制。

**Task**: 为长沙红中麻将平台实现完整的加密货币支付集成模块。支持 BTC/ETH/USDT (ERC20/TRC20) 多链支付，包含订单创建、支付地址生成和多币种配置。全部数据通过浏览器 localStorage 模拟存储（不实际调用外部支付网关）。

**Context**:
- 语言: JavaScript ES6+，浏览器环境
- 支付网关: 模拟实现（可替换为真实网关）
- 存储: localStorage（模拟区块链交易状态）
- 币种配置: BTC(3确认), ETH(12确认), USDT-ERC20(12确认), USDT-TRC20(12确认), SOL(1确认)

**Detailed Requirements**:

1. 币种配置对象（地址正则、确认数、精度、区块链浏览器URL）
2. 订单创建函数（生成唯一支付地址、二维码URL、过期时间）
3. 状态查询函数（pending→paid→completed/expired）
4. 地址格式验证函数（按币种正则校验）
5. 价格换算辅助函数

**Constraints**: 纯前端模拟，不涉及真实转账。所有 key 以 mj_crypto_ 为前缀。

### 02. Webhook 处理与安全（原03+05）

**Role**: 你是支付安全工程师，精通 Webhook 签名验证、重放攻击防御和幂等性设计。

**Task**: 实现支付回调处理模块。核心需求：正确验证签名、防止重放攻击、确保幂等性（不重复充值）、记录审计日志。

**Context**:
- 模拟支付网关回调: 由定时器模拟触发
- 签名方案: HMAC-SHA256
- 防重放: Nonce + 时间戳（5分钟内有效）

**Detailed Requirements**:

1. verifySignature(body, signature, secret)：HMAC-SHA256 签名验证
2. ReplayAttackProtection：Nonce + 时间戳 + Redis 模拟（localStorage）检查
3. handleWebhook：幂等校验（订单已 completed 则跳过）、更新订单状态、充值用户余额
4. 审计日志：所有支付操作记录不可篡改日志（时间戳+操作+金额+地址脱敏）

**Constraints**: 
- 非法签名→拒绝
- 重复 nonce→幂等跳过
- 密码从环境变量读取，非硬编码
